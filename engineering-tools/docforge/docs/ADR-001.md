Title: Adopt a Document Intermediate Representation (IR)

Decision:
DocForge will use a canonical, format-independent Document IR as the internal representation for all processing.

Rationale:

Decouples readers from generators.
Enables a single normalization pipeline.
Supports multiple output formats without re-parsing.
Provides a stable foundation for AI processing and semantic analysis.
Makes testing easier by allowing pipeline stages to be exercised against a common representation.

Consequences:

Readers convert external formats into the IR.
Processing passes operate only on the IR.
Generators consume the IR to produce output formats.
The IR becomes a versioned public contract within the project.
Recommendation Before Coding

At this point, I would freeze four core specifications:

DF-PRS-001 — Product Requirements Specification
DF-ADS-001 — Architecture Design Specification
DF-DDS-001 — Detailed Design Specification
DF-001 — Document IR Specification
