DF-001 — Document IR Specification

Document ID: DF-001
Version: 0.1
Status: Draft

1. Design Goals

The IR should be:

Format independent (not tied to DOCX or Markdown)
Semantic (capture meaning, not formatting)
Loss-aware (record unsupported features instead of silently dropping them)
Serializable (JSON/YAML)
Extensible
AI-friendly
2. Root Object

├── Metadata

├── Blocks
├── Assets

15. Loss Policy

One principle I'd like to formalize:

Never silently discard information.

If an input feature cannot be represented:

Preserve it as a Raw node where practical.
Or attach a diagnostic explaining what was omitted or transformed.
Continue processing rather than failing the entire document.

This makes the pipeline predictable and transparent.

16. Versioning

The IR itself should have an independent version.

ir_version: 1.0

This allows readers and generators to evolve while maintaining compatibility.
